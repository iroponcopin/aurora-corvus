Overview: Installing the Alpha pack

Alpha (formerly Glimpse Alpha, and Sorakaze before that) is the group of Fabric mods installed on the Sorakazekarasu server. It's made up of 11 independent mods, each of which can be installed and updated separately. It doesn't replace or remove vanilla (unmodded) content like bows or minecarts — instead, it adds new items, blocks, and dimensions.

ModWhat it adds
GunsRanged weapons vanilla doesn't have (Assault Rifle, Shotgun, Sniper Rifle, and more)
RailA train that gradually speeds up, plus couplable passenger and freight cars
Building & DecorCity-building materials like traffic lights and guardrails, plus appliances like security cameras, ATMs, and elevators
VehiclesCars, buses, aircraft, and more
BossPowerful bosses to fight, and their dedicated drops
SkyA new dimension called "Sky," and the angel city and kingdom that live there
SurvivalNew ores, armor, and life-support features like temperature and the seasons
PowerPower generation and transmission networks, plus electric devices
BackroomsSanity-driven exploration of a hidden liminal area, reached through a rift near End Cities

For a detailed list of each mod's items and recipes, see the Recipes page; for what's changed so far, see the Changelog.

You need "Fabric" to use mods

Fabric is the foundation that lets Minecraft load mods. Think of it like needing a game console's base system before you can install any software on it — before installing the mods themselves, you first need to install Fabric on both the server and each player's PC.

⚠ The single easiest thing to get wrong

Mods need to be installed not just on the server, but on the PC of every single person playing. Installing them on the server does not automatically apply them to everyone. Unless the server and every player have matching Minecraft versions, Fabric, and mods, no one can join the server.

Who needs to set up what

  • The server (the Sorakazekarasu server) — Fabric server + Fabric API + the 11 Alpha mods
  • Each individual player's PC — Fabric client + Fabric API + the 11 Alpha mods (must exactly match the server's combination)
This site doesn't distribute the mods themselves

This site only hosts "reading material" — recipe tables, changelogs, install instructions, and the like. It does not distribute the mods themselves (the jar files). Please get the full set of jar files you need from your server admin.

How this page is organized

This guide is split into two audiences. Most people only need to read the chapter for players to be able to join. If you're the one running or administering the server yourself, please also read on to the chapter for server admins.

Currently supported versions (as of writing)

For Players

For Players: Setting Up to Join the Server

This covers what to set up if you're joining someone else's server to play. No technical expertise required. Follow the steps in order and it should take about 15-20 minutes.

Only 3 things to do
  • ① Install Fabric (the foundation that loads mods) on your PC
  • ② Put the set of mod files you got from the server admin into the right folder
  • ③ Change one launch setting and join the server

What you'll need

  • A Windows or Mac PC that can run Minecraft: Java Edition
  • The full mod set from your server admin (12 jar files = 1 Fabric API + the 11 Alpha mods)
🛑 Very important

You can't join unless you have the exact same version and exact same mod files as the server. This page uses Minecraft version 26.2 as an example, but if your server admin gave you a different number, use that instead. Please don't double-click to open the jar files you received — just placing them in the folder is all you need to do.

① Install Fabric

Open https://fabricmc.net/use/installer/ and get the installer. Stay on the "Client" tab (don't switch to "Server"), pick the same Minecraft Version as your server, and click "Install."

On Windows

  1. Download the installer from a button like "Download installer (Windows/.exe)" on the page, then double-click it to run it (if you see "Windows protected your PC," click "More info" → "Run anyway").
  2. Staying on the "Client" tab, pick 26.2 (the same number as your server) for Minecraft Version, leave Loader Version as-is, and click "Install."

On Mac

  1. Download the installer (.jar) via the "Download universal jar" button. There's no Mac executable (.exe).
  2. For the downloaded fabric-installer-….jar, don't just double-click it — right-click it (or control-click) and choose "Open." If you get a warning, click "Open" again.
  3. Staying on the "Client" tab, pick the same Minecraft Version as your server and click "Install."
⚠ If your Mac says "cannot verify the developer"

On recent versions of macOS, even right-click → "Open" may not show a button, and you might just see a warning saying "'fabric-installer….jar' cannot be checked for malicious software." If that happens, you can open it this way instead:

  1. Click "Done" on the warning (never click "Move to Trash")
  2. Open the Apple menu (top left) → "System Settings" → "Privacy & Security"
  3. Scroll down to find a message saying "'fabric-installer….jar' was blocked," and click "Open Anyway" next to it
  4. If asked again, click "Open Anyway" → enter your Mac password (or use Touch ID)

This is the standard warning macOS shows for anything not registered with Apple, and it's nothing to worry about as long as you got it from the official Fabric site. Once you allow it, it'll open normally from then on.

If nothing happens when you run the installer on Mac

If right-click → "Open" does nothing at all, Java isn't installed on your system. Go to adoptium.net, install the macOS installer (.pkg) for "Temurin," and try again. Choose "aarch64" for Apple Silicon Macs (M1/M2/M3/M4, etc.) or "x64" for Intel Macs. If you're not sure which, check the "Chip" field under the Apple menu (top left) → "About This Mac" (if it says "Apple M…," you want aarch64).

② Put the mod files in the mods folder

Windows: %appdata%\.minecraft\mods

  1. Type %appdata%\.minecraft into File Explorer's address bar and press Enter.
  2. If there's no mods folder, create one (all lowercase).
  3. Copy all 12 jar files you received into this mods folder (no need to unzip — drop the jars in as-is).

Mac: ~/Library/Application Support/minecraft/mods

  1. Click the desktop once, then press ⌘ command+⇧ shift+G together (or use the menu bar's "Go" → "Go to Folder…").
  2. Paste ~/Library/Application Support/minecraft exactly as-is into the box that appears and press Enter (don't forget the leading "~"). "Library" is normally hidden in Finder, so this is the reliable way to get there.
  3. If there's no mods folder, right-click in that window and choose "New Folder" to create one.
  4. Drag and drop all 12 jar files you received into this mods folder.

③ Launch with Fabric and join the server

  1. Open the Minecraft launcher and, from the list of launch profiles near the "Play" button, pick something named like fabric-loader-26.2 (staying on "Latest Release" will launch without any mods).
  2. Click "Play" to launch as usual. If a "Mods" button has appeared on the title screen, it worked — clicking it will show all 11 Alpha mods plus Fabric API.
  3. From there, connect to the server through "Multiplayer" as usual.

When the mods get updated

Whenever the server-side mods are updated, everyone joining needs to update to the same version at the same time.

  1. Get the new mod files from your server admin (wait for their announcement before doing this).
  2. Open your mods folder, delete the Alpha jar files that were there before, then add the new ones (even if the filenames changed, they're treated as the same mod — leaving old ones in place will prevent launch).
  3. Launch with the fabric-loader profile as usual.
⚠ Note

If only one side is on the new version, you won't be able to join. If you get stuck, check the FAQ too.

The steps are the same whether you're on Apple Silicon (M1/M2/M3/M4, etc.) or an Intel Mac — the only difference is picking aarch64 vs. x64 when choosing Java (Temurin).

For Server Admins

For Server Admins: Preparation (Backup & Version Check)

From here on, this chapter is for whoever runs and administers the server itself. It walks through adding Fabric and the 11 Alpha mods to a Minecraft server that's already running vanilla (a standard, unmodded server). This chapter uses a Windows server as its example. If you're running your server on Mac / Linux, translate the folder locations and command steps to your own environment and follow the same general process (per the official Fabric site's instructions).

🛑 Before you do anything

Always take a backup before you start, so a failed mod install can't cost you your world.

1. Back up your world

Open your server's folder (e.g. C:\MinecraftServer) and run whatever backup process you normally use (e.g. a backup script like Backup-Server.bat). If you don't have a dedicated script, it's fine to just stop the server and copy the entire world folder somewhere else.

2. Check your Java version

  1. Open Command Prompt (or any terminal).
  2. Type java -version and press Enter.
  3. Check whether the number shown is 25 (e.g. java version "25.0.3").
🛑 Very important

Running Minecraft 26.2 requires Java 25. Older setup instructions sometimes say "Java 21," but that's outdated — the server won't start with Java 21. If your number is below 25, go to adoptium.net, download and install "Temurin 25 (LTS)," restart your computer, and check again.

3. Check the server's Minecraft version

  1. Start the server up once, the way you normally would (e.g. Start-Server.bat).
  2. Look near the top of the console (the black window) for a line like Starting minecraft server version X.Y, and note the number.
  3. Type stop in the console and press Enter to safely shut the server down.
⚠ Note

This guide uses "26.2" as its example, but if the number you actually found is different, use that number in every step from here on (when selecting Fabric, Fabric API, and mod versions). If the server, every player, and the mods don't all match on version, nothing will work at all.

For Server Admins

For Server Admins: Installing Fabric

Install the Fabric server

  1. Open https://fabricmc.net/use/server/ in your browser and download the installer from a button like "Download installer (Windows/.exe)."
  2. Double-click the downloaded fabric-installer….exe to launch it (if you see "Windows protected your PC," click "More info" → "Run anyway").
  3. On the installer's settings screen, check these 4 things:
    • Select the "Server" tab
    • Set Minecraft Version to match the server version you confirmed earlier (e.g. 26.2)
    • Loader Version can stay as-is
    • Set Install Location to your existing server folder (e.g. C:\MinecraftServer)
  4. Click "Install."
  5. If a new file called fabric-server-launch.jar now exists in your server folder, it worked.

Create a new launch file (batch file)

Your existing launch file (e.g. Start-Server.bat) launches the server "without mods." Leave it in place (so you can go back to a mod-free server if you ever need to). Instead, create a new launch file for Fabric.

  1. Open Notepad.
  2. Copy and paste in the following as-is: 
    @echo off
cd /d "%~dp0"
title Minecraft Fabric Server
java -Xms2G -Xmx4G -jar fabric-server-launch.jar nogui
echo Server stopped.
pause
  3. Choose "File" → "Save As," and save it to your server folder (e.g. C:\MinecraftServer) with the filename Start-Fabric-Server.bat, setting "Save as type" to "All Files."
⚠ Note

If you don't set "Save as type" to "All Files," you'll end up with a non-functional file named Start-Fabric-Server.bat.txt. Also, if your server was set up with a memory (RAM) allocation other than 4GB, change the "4" in -Xmx4G to match.

For Server Admins: Installing the Mods & Verifying Startup

Each mod is a single file called a "jar" file. You install it just by putting it in your server folder's mods folder.

1. Set up the mods folder

Check whether your server folder (e.g. C:\MinecraftServer) has a folder named mods. If not, right-click → "New" → "Folder" and name it mods (all lowercase).

2. Get Fabric API

Open https://modrinth.com/mod/fabric-api/versions and download the topmost entry whose "Game version" matches your server (e.g. fabric-api-0.154.2+26.2.jar).

3. Put the full mod set in the mods folder

Copy all 12 jar files — 1 Fabric API + the 11 Alpha mods — into the mods folder (no need to unzip — drop the jars in as-is). Get the 11 mods themselves through whatever distribution channel you've been using. This site does not distribute the mods themselves.

Once you've confirmed it starts up, walk everyone joining through the chapter for players so they can install the same Fabric and mod set on their own PCs.

For Server Admins

Updating to a New Mod Version

Since the Alpha pack's 11 mods are each fully independent, an update doesn't necessarily mean all 11 get replaced. You only need to swap out the mods whose contents actually changed (check the distribution notes or the Changelog to see which mods were touched).

Update steps

  1. Type stop in the server console to shut it down.
  2. Back up your world using your usual backup process.
  3. In the server's mods folder, delete the old jar file(s) for the mods being updated, then add the new jar file(s) (having both old and new versions of the same mod present will prevent startup).
  4. Start the server with Start-Fabric-Server.bat and confirm the console shows the updated version.
  5. Distribute the new jar files to everyone joining and have them swap them out the same way (see the chapter for players). No one can join if only the server or only players are on the new version.
🛑 Very important

If you start the server with a mod completely removed (rather than just updated), any blocks placed or items held that belong to that mod (like traffic lights) will disappear. This is how Minecraft and Fabric work, and it can't be undone. Always back up before removing a mod.

About config files (the auto-repair mechanism)

Every mod automatically generates a config file (e.g. sorakaze_guns.json) inside the config/ folder on startup. You can adjust values like damage and speed there, and you generally never need to manually delete or edit it with each update.

💡 How it currently works

When a new release changes a default value, it's automatically updated to the new default only for settings you haven't touched yet (ones still sitting at an old default). Values you've tuned yourself are never touched. Newly added settings are also automatically appended on startup. Whatever gets updated is always logged in logs/latest.log as "old value → new value."

⚠ Note on editing config files by hand

If you manually delete just part of a value inside a config file (e.g. removing only the damage line from one weapon's settings block), that item can silently fall back to a different internal default from inside the mod itself (with no error shown). If you want to adjust a specific number, edit that value directly instead. If you want to reset a mod's settings to defaults entirely, delete that mod's whole config file — it'll be rebuilt with defaults the next time the server starts.

Things to Know Before You Play

The Alpha pack includes a handful of changes that affect vanilla behavior. This section covers the ones that are especially easy to miss. Since fine details can be adjusted with any update, also check the Changelog and Known Issues pages for the latest status. Config adjustments are something your server admin handles.

Redstone now needs "electricity"

With the Power mod installed, part of vanilla redstone no longer works on its own.

  • Now requires electricity: redstone dust, repeaters, comparators, redstone blocks, and redstone torches. None of these will output a signal until they're wired to electricity via cable. Auto-farms, stations, automatic doors, and hopper lines will all stay shut down until you wire them up.
  • Still work without electricity, as before: levers, buttons, pressure plates, tripwire hooks, observers, daylight sensors, sculk sensors, targets, trapped chests, detector rails, lecterns, jukeboxes, lightning rods, and more. Manually opening doors and gates also works as usual.
  • A redstone block naturally breaks about 10 minutes after being placed (returning to your inventory as an item).
💡 How to revert this (for server admins)

Setting powerEnabled to false in config/sorakaze_power.json disables redstone electrification entirely.

Some Building & Decor devices also need electricity

5 devices — the security camera, elevator, escalator, automatic door, and ATM — won't work unless they have electricity wired in via cable (the elevator still works "going down" even without power). Setting the corresponding option to false in config/sorakaze_deco.json lets you make electricity optional for each one individually.

Generators heat up rooms

Running generators and nuclear plants raise the temperature of the space they're in. Only air conditioners can cool it back down. Sectioning off your machine room with walls and a closed door is an easy way to keep the heat from spreading to other rooms. This feature itself can be disabled by setting temperatureMachineHeatEnabled to false in config/sorakaze_survival.json.

The Sky world's height has been extended

With the Sky mod installed, the maximum build height in the Overworld has been raised. Only the upper limit changes — the depth underground (the bottom of the world) and existing terrain are unaffected.

The Rocket Launcher destroys terrain

By default, the Guns mod's Rocket Launcher destroys terrain at its point of impact. Setting the vanilla game rule mobGriefing to false does not stop this. To stop the destruction, you need to set rocketDestroysTerrain to false in config/sorakaze_guns.json. Be especially careful near your base.

About gun damage

The Guns mod's weapons — especially the Assault Rifle — deal extremely high damage, and many of the mod-added bosses can be killed in a matter of seconds. If you want more of a challenge, your server admin can restore the difficulty by adjusting each weapon's damage value in config/sorakaze_guns.json.

Removing a mod deletes any blocks/items it added

This is how mods work in general, not a bug specific to Alpha. Any blocks placed or items obtained while a mod was installed will be lost from the world if that mod is removed. The only way to undo this is to restore from a backup.

FAQ & Troubleshooting

Frequently asked questions

QuestionAnswer
Will my world get deleted?No. Installing Fabric doesn't touch your existing world — it keeps working as-is. If you're worried, always take a backup before installing.
Can a friend without the mods join?No. Every player needs to complete the setup in the chapter for players.
I want to go back to no mods (vanilla)On the server side, just launch with your original no-mods launch file to go back to vanilla (any blocks/items added by the mods will disappear).
Updating the mods suddenly broke thingsCheck whether the mod versions match between the server and players. You can't join if only one side is on the new version.
I don't understand the error messageThat's fine — you don't need to. Just send the latest.log file, found inside the logs folder, directly to your server admin as-is.

If the server won't start

  1. Temporarily move everything out of the mods folder to somewhere else.
  2. Add files back one at a time, restarting each time, to find out which one is causing the problem.
  3. If you see Java-related errors, check your Java version — see the preparation chapter.

If you can reach the server but can't connect

  1. Check whether every player's version and mod set exactly matches the server's.
  2. Mismatched Fabric API versions are an especially common culprit, so check that first.
💡 If nothing fixes it

Send logs/latest.log to your server admin and ask for help. No need to panic — as long as you have a backup, you can always get back to where you were.

Server Admin app: "wrong id or password" even though it should be right

The in-game PC's Server Admin app deliberately shows the exact same message for every reason a sign-in can fail, so it never hints to an attacker which part was wrong. That means a correct ID and password can still be refused if:

  • No admin account has been set up on the server yet. By default, the app ships with zero admin accounts — nobody can sign in until the server admin creates one with tools/make_admin_account.py (from the mod's source repository) and places the result at config/sorakaze_deco/admin_account.json on the server, then restarts it.
  • The ID or password itself is wrong. As of V2.4.4, sign-in uses a single shared ID and password — anyone who knows both can sign in from any Minecraft account, so a per-player name mismatch is no longer a possible cause.

If you're the server admin and sign-in still fails after checking both of the above, restart the server (this also signs everyone out, so old passwords stop working immediately) and check the server's log for a line starting with ADMIN: — it explains exactly why the account file couldn't be used, without ever printing the password itself.

How to restore a world from backup (for server admins)

  1. Type stop in the server console to shut it down.
  2. Grab the most recent backup from wherever they're stored (e.g. C:\MinecraftServer\backups) (if it's a zip, right-click → "Extract All").
  3. Swap the extracted world folder in for the world folder inside your server folder (overwriting it).
  4. Start the server.
