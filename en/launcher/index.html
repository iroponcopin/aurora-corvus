What's New · Version 3.0.1

Corvus Store 3.0.1 is a small release with two changes.

The Updates page now works the way the App Store's does. It has no "Check for Updates" button and no line about when it last checked. It checks by itself when you open it (unless it checked a moment ago), every fifteen minutes while Corvus Store is open, and when you press Cmd+R (Ctrl+R on Windows and Linux). When two or more updates are waiting, an "Update All" button (すべてアップデート in Japanese) appears at the right end of the page's title and updates them one after another, Corvus Store itself last; with only one waiting there is no such button. It never starts a first install, it does not try an update twice, and if something else is writing into your mods folder it stops instead of refusing card by card.

The picture beside your name was a black disc in 3.0.0 — in the sidebar and at the top of the account sheet, for every account picture and every monogram. The ring that outlines the picture had lost its style when the old settings panels were removed, and a circle is filled black unless told otherwise. It is now a hairline and nothing else, and a picture with see-through pixels sits on the card's grey. That was a fault of 3.0.0, and nothing you did.

The official icons of OUKA, Cherry, Aureum, Tsubomi, Noctua and ASTRAEA, which came with 3.0.0, are unchanged. Everything else is 3.0.0.

Verified: 913 unit tests pass on each of two clean builds, with the compiler set to refuse any warning, and the two builds made byte-identical programs. The Store was drawn without a window in all 13 languages (138 checks each, English, Japanese and Arabic included), including a check that reads the account picture pixel by pixel — with the 3.0.0 code it reads black, and with this one it reads the picture — and the Updates page: no check button, one check when it is entered, Update All appearing at two waiting updates and gone at one, and going through them in turn with Corvus Store last. It was run against the real update check with a manifest served from this machine (38 checks). The built application was driven in a real window twice: all 94 of the window instrument's claims held, none failed, none were undecided, including that Cmd+R starts one check and that opening Updates after a while starts one. Perch's own instrument, on this build: 47 claims held in each of two runs, none failed, and three in each could not be decided because the machine was busy (Perch is unchanged since 3.0.0). The macOS installer, built by CI, was opened here and the app inside it run: it reports 3.0.1, opens its window and draws all five screens, with no check button on Updates and the account picture showing; it is built for Apple Silicon Macs only. Not verified, and worth saying: the fifteen-minute wait itself (the decision is tested, the timer is the system's); an Update All run against real downloads (the order and the stopping are tested with stand-ins; the installs it presses are the same ones GET and UPDATE press); a slow check is invisible, because the cards keep showing what they showed while one runs; Corvus Store replacing itself on an installed copy; the Windows and Linux installers, which nobody has installed or run; and the words "Update All" in the twelve languages other than Japanese, which nobody who speaks them has read.

Guide

Corvus is a small desktop app that keeps your mods up to date automatically. It checks this Wiki for the current release, downloads updates for you, and verifies every file it downloads against a SHA-256 checksum published here before it touches your mods folder. This Wiki is the only source it trusts.

This guide was written for earlier versions of Corvus. Corvus Store 3.0 has new screens, so some steps may differ.

What it is, and why it exists

Keeping mods up to date by hand means re-visiting the Download page, comparing version numbers, downloading a new file, and putting it in the right folder every time a release ships. Corvus automates that: it reads this Wiki's release manifest, compares it against what you already have installed, and fetches only what's changed.

Every download the launcher makes is checked against a SHA-256 checksum published by this Wiki before it's used. If a downloaded file doesn't match, the launcher will not install it. The Wiki is the launcher's only source of truth for what the "current" release is.

Installing Corvus

Corvus is available from the Download page on this Wiki in two forms:

  • Native installers (a Windows .msi, a macOS .dmg, a Linux .deb) — install like a normal desktop app, no Java required. These are not code-signed yet, so your OS will show a first-run warning: on macOS, right-click the app and choose Open instead of double-clicking; on Windows, click "More info" then "Run anyway" on the SmartScreen prompt.
  • The cross-platform jar, corvus-3.0.1.jar — the same file runs on Windows, macOS, and Linux, but needs Java 25 or newer already installed. If double-clicking it doesn't open it, run java -jar corvus-3.0.1.jar from a terminal or command prompt in the folder you downloaded it to.
Pointing it at an existing pack folder

If you've already installed mods manually, you don't need to start over. On first run, the launcher lets you choose the folder your mods already live in instead of creating a new one. Point it at your existing mods folder and the launcher will treat that installation as the one it manages from then on.

Automatic vs. manual update mode

In automatic mode, the launcher checks this Wiki's release manifest on its own and installs new versions as soon as they're available, so your pack folder stays current without you having to do anything.

In manual mode, the launcher still checks for updates, but waits for you to review and confirm before it downloads or installs anything — useful if you'd rather choose exactly when an update lands, for example to avoid interrupting a play session.

Confirming an update actually applied

As of version 1.1.0, clicking Update writes the new mod files directly into your pack's mods folder, and the launcher will not show "Update complete" unless it has re-checked the folder afterwards and confirmed the expected files are really there. If something goes wrong partway through, it reports failure instead of a false success.

To see the change for yourself on macOS: open the folder shown under General (⌘+⇧+G in Finder, then paste the path), look inside mods, and check the version number in each cherry-*.jar filename before and after clicking Update.

If you're updating from a pack folder that was last touched by a launcher older than 1.1.0, the very first update may leave one old-versioned jar sitting alongside the new one for that mod (the launcher didn't yet have a record of which files it had previously placed). This clears up on its own from the next update onward. If it bothers you sooner, it's safe to delete the older-numbered cherry-*.jar by hand once the new one is confirmed present.

Restoring from a backup if an update goes wrong

If an update leaves your pack in a state you don't want — a mod misbehaving, or an update you'd rather undo — the launcher keeps a backup of your previous pack state so you can restore it. Use the launcher's restore option to roll your pack folder back to the backed-up version rather than trying to fix files by hand.
