ガラスランタン(52種)

建材MODに新しく52種類のガラスランタンが追加されました。内訳は バニラ色ガラス版18種 + 補強版17種 + 停電(暗色)版17種です。

  • 光レベルは最大の15。実測で、既存のLEDパネルより明るい発光テクスチャになっています
  • アイテムグループでは、機能ブロックタブの海のランタンの隣に並びます

バックルームズ

画面UI

画面左手にガラス製の目標パネルが常時表示されます。現在の階層・正気度・次に向かう場所などがひと目で分かります。

階層1「ロビー」

見本のような小部屋ではなく、実際に歩いて探索できる本物のロビーです。終末の都市の裂け目から入ります。

正気度がのどの渇きの代わりに

バックルームズの中では、通常の「のどの渇き」ステータスの代わりに正気度(サニティ)が生活の軸になります。

⚠ 通常の武器は効きません

バックルームズの中に出現する怪異は、通常の武器での攻撃が一切効きません。また、これらの怪異は倒すことができません。戦うのではなく、避けて進むための場所です。

地上の襲撃

これまで村の襲撃には「不吉な予感」の効果が必要でしたが、V2.2からは「不吉な予感」なしでも、村にいるだけで純粋な確率により襲撃が発生するようになりました。

  • 村にいる間、一定時間ごとに一定確率で発生します
  • 全12波構成。最終波には天界MOD由来の追加の敵が加わります

砲台(銃・弓を据え付ける)

砲台を右クリックすると、手に持っている銃や弓・クロスボウをその場に据え付けられます。据え付けた武器には弾薬用の内部インベントリがあり、外すと武器と残弾がそのまま返ってきます。

動画(4K対応・自動停止)

動画再生の対応解像度がこれまでの上限から引き上げられ、最大4Kまで再生できるようになりました。画面の縦横比は常に16:9に保たれます。

画面から一定距離離れると、再生が自動的に停止します。

Sparxie の杖

これまで近接攻撃のみでしたが、V2.2からは近接攻撃と遠隔攻撃の両方が使えるようになりました。遠隔攻撃では射程24ブロックのボルトを放ちます。

銃火器の調整

  • ミニガンの威力が約3倍になりました
  • ロケットランチャーの爆発の威力が大幅に強化されました

内部の設定値そのものはここには載せていません。実際の使用感で確かめてください。

ドローンとドローンアプリ

自由に飛ばせるカメラドローンが追加されました。専用のドローンアプリ(スマホ)から、ドローンの視点を16:9のライブ映像として見られます。

手を離すとその場でホバリングして待機します(自動で手元に戻ってくる仕様ではありません)。

札幌再現(Sapporo)

実在する北海道札幌市を、実際の地理データから再現したディメンションです。誇張なく、正直な内訳は次のとおりです。

  • 建物の輪郭(フットプリント): 100% 実データ(OSM由来。以前は約20%のみでした)
  • 地形: 100% 実データ(国土地理院のDEM=数値標高モデル由来)
  • 建物の高さ: 一部のみ実データ。PLATEAU(国土交通省の3D都市モデル)のデータがまだ取得できていないため、高さの大部分は地区ごとの統計にもとづく推定値です。将来PLATEAUデータが入手でき次第、より正確な高さに更新される予定です

「建物の高さが推定である」ことを隠さずに書いています。輪郭と地形は本物の測量データそのものです。

書かれていなかった仕様

ここに挙げる7つは、すべて現在配布中のバージョン(V2.5.1)のパックに実際に入っていて、既定で動いている仕組みです。今日から始まる新機能ではありません。ガソリンと原子力発電所の大気汚染は、追加されたこと自体はV2.0.0の更新履歴で触れていましたが、既定で有効なことや設定でオフにできることまでは書いていませんでした。残りの5つ(天候システム・物価倍率・ダイヤモンドATM・のどの渇きによる死亡・仮面の耐久システム)は、更新履歴に一度も載ったことがありません。今回、実際のMODのコードを1つずつ確認しながら、まとめて書き起こしました。

ここに書いた数値はすべて、V2.5.1のMODのコードで直接確認したものです。どの項目も、サーバーの config ファイルでオン/オフや細かい数値を調整できます。設定を変えたい場合は、サーバー管理者にご相談ください。

天候システム(吹雪・台風・地震・津波・火山)

サバイバルMODに、5種類の天候・災害システムが入っています。吹雪・台風・地震・津波・火山で、いずれも既定で有効です(blizzardEnabled / typhoonEnabled / earthquakeEnabled / tsunamiEnabled / volcanoEnabled、すべて config/sorakaze_survival.json)。

  • 吹雪・台風・津波は、視界や移動・体温(吹雪)、飛翔物や降雨量(台風)、内陸への浸水(津波。パック独自の有限の水の仕組みの上で動きます)に影響しますが、この3つはブロックを一切壊しません。
  • 地震は、既定のままでも一部のブロックを実際に壊します。earthquakeDamagesPlayerBuilds(既定false)が切り替えるのは「それ以外の素材まで壊すかどうか」だけで、被害そのものを止める設定ではありません。earthquake_fragileタグに載っているブロック——石・丸石・苔むした丸石・深層岩の丸石・砂岩・赤砂岩・土・砂・砂利・粘土など、ごくふつうの建材——は、この設定に関係なく壊れます。チェスト・かまどなどブロックエンティティを持つブロックだけは、この設定に関係なく絶対に壊れません。
  • 火山は実際にクレーターを掘りますが、建築物を巻き込まないための関門が2つ独立して働きます。地震が起きるたびに5%の確率(volcanoEruptionChancePerEarthquake = 0.05)で噴火し、噴火地点を中心に半径6ブロック・深さ4ブロック(volcanoCraterRadiusBlocks / volcanoCraterDepthBlocks)のクレーターを実際に地形ごと掘り、既定では溶岩で満たします(volcanoLavaEnabled = true)。ただしその前に、噴火地点から24ブロック以内にブロックエンティティが1つでもあれば、噴火は場所をずらさずまるごと中止されます(volcanoVentClearanceBlocks = 24)。さらに、掘る範囲に「掘ってよい自然地形」のリストに無いブロックが1つでも含まれていても、同じくまるごと中止されます。MOD自身のテストは、木の板を敷いた床だけでこの中止条件を確認しています。実際に巻き込まれるおそれがあるのは、周囲24ブロックにブロックエンティティが無く、かつ石・土・砂・砂利など自然素材だけでできた建物に限られます。

物価倍率(×10〜×100)

天空(Sky)と二相楽園(Planarcadia)の2つのMODで、このMODスイートが独自に定めている価格(バニラの村人取引は対象外)が、商品ごとに10倍から100倍のあいだでランダムに引き上げられています。既定で有効です(priceMultiplierEnabled = true、それぞれ config/sorakaze_sky.json / config/sorakaze_planarcadia.json)。

  • 倍率は商品ごとにワールドのseedから1回だけ決まり、以後は変わりません。同じワールドで同じ商品を2回買っても倍率は同じです。店やタイミングで動く「相場」ではありません。
  • 例:天空のシンガポール不動産は、定価100万〜1,000万エメラルドのところ、この仕組みにより実質1,000万〜10億エメラルドになります。
  • 銃火器・鉄道・電力・バックルームズの4つのMODにも、同じ倍率計算のコードが(MOD間で参照を持たない設計上の都合で)複製されていますが、V2.5.1時点ではどの価格からも呼び出されていません。この4つのMODでは、今のところこの仕組みは実際には何も変えていません。
  • この×10〜×100には例外が1つあります。天空MODの安価な商品(食料・王族の矢・天空ブロック)の一部は、いまもバニラの取引画面で売買されており、この画面は一度に最大1,152エメラルド(支払い枠2つぶん)までしか受け取れません。抽選された倍率どおりの価格がこれを超える場合、実際に請求される額はこの上限で頭打ちになります——つまり実際に載る倍率が、抽選値より低くなることがあります。装備や不動産(上のシンガポールの例を含む)はATM・台帳を通した決済のため、この上限の影響を受けません。

ダイヤモンドATM(ダイヤ残高)

建材・装飾MODのATMに、エメラルド残高とは別の「ダイヤモンド残高」が既定で入っています(atmDiamondBalanceEnabled / atmDiamondExchangeEnabled、ともに既定 true、config/sorakaze_deco.json)。口座の種類(個人/共有/特別)は、既存のエメラルド口座とまったく同じものを使いますが、利息の仕組みは別です。

  • ダイヤとエメラルドの残高は合流しません。両替はATMの画面から行い、レート(1ダイヤ=4エメラルド)はバニラの取引実績にもとづく固定値で、config からは変更できません。
  • ダイヤ残高には利息が一切つきません。これは意図的な設計です。エメラルド口座は利息を計算するための最終計算時刻をデータに持っていますが、ダイヤ残高のデータ形式にはこの時刻がそもそも存在せず、あとから複利を付けようとしても基準になる時刻がありません。これは、エメラルドATMの「利息は1,000万エメラルドちょうどで頭打ちになる」という既存の仕様を守るためのものです。ダイヤ残高にも利息がついてしまうと、この上限が静かに実質的な意味を失ってしまいます。

原子力発電所の大気汚染(遡及適用)

電力MODの原子力発電所が周囲の空気を汚し、汚染地域にいると鈍化→弱体化→毒の順でデバフを受ける仕組み自体は、V2.0.0の更新履歴で一度紹介しています。今回あらためて書くのは、次の2点です。

  • 既定で有効です(pollution.enabled = true、config/sorakaze_power.json)。
  • 遡及的に適用されます。この仕組みが入る前から建てて稼働させていた原子力発電所も、パックがこの仕組みを持つバージョンに更新された瞬間から汚染を始めます。移行期間や、既存の発電所だけを除外する設定はありません。

空気清浄機を稼働させておけば、汚染地域は既定で60秒ほどで安全になる設計です(実測ではおよそ54秒)。最も重い毒の段でも体力が1未満になることはなく、汚染地域から出れば効果は既定で6秒ほどで自然に切れます。

のどの渇き(水分)による死亡

サバイバルMODには、満腹度とは別に「水分」ゲージがあり、既定で有効です(hydrationEnabled = true、config/sorakaze_survival.json)。水分は最大20で、じっとしていれば90秒(1,800tick)に1ずつ、走っている間やパック内の「暑いディメンション」にいる間はさらに早く減ります。

  • 水分が0になると、バニラの空腹と同じ条件でダメージが始まります(4秒ごとに1ずつ。イージーは体力10、ノーマルは体力1で止まり、ハードでは死ぬまで続きます。ピースフルでは水分自体が減りません)。
  • 水分が0のまま10分(hydrationDehydrationEscalationTicks = 12000)続くと、ダメージが30秒ごとに0.1ずつ増え、最大で4秒ごとに1.4(秒あたり0.35)まで上がります。さらにこの時点からは、イージー・ノーマルでもダメージが体力10や1で止まらなくなります(hydrationDehydrationEscalationIgnoresDifficultyFloor = true)。つまりピースフル以外のどの難易度でも、水を飲まないまま10分経つと、のどの渇きだけで実際に死ぬことがあります。
  • 水筒や水入りボトルを飲めば回復します(1回につき水分+6)。

車両のガソリン

乗り物MODにガソリンが必要になったこと自体は、V2.0.0の更新履歴で紹介済みです。今回あらためて書くのは、オン/オフを切り替えられることと、既存の乗り物の扱いです。

  • 電車を除くすべての乗り物がガソリンを消費します。既定で有効です(gasoline.enabled = true、config/sorakaze_vehicles.json)。false にすると、この仕組みが入る前と同じ「燃料無限」の挙動に完全に戻ります。
  • この仕組みが入る前から置いてあった乗り物は、更新後も満タンの状態で引き継がれます(legacyVehicleFillFraction = 1.0)。置いた瞬間に動かなくなることはありません。

仮面(マスク)の耐久システム

Sparkleの仮面・Sparxieの仮面に、耐久システムが既定で入っています(maskBreakRevivalEnabled = true、config/sorakaze_survival.json)。

  • 耐久は814(maskDurability。当初の仕様書は「800程度」でしたが、実装値は814です)。使い切ると仮面が割れます。
  • 割れてから320秒(6,400tick、maskRevivalCooldownTicks)経つと、また使えるようになります。ただしこの復活は一度限りです。2度目に割れたら、その仮面はそこで終わりです。
  • 「一度割れた」という記録は仮面本体に残り、再ログイン・死亡・チェストへの出し入れ・サーバー再起動をまたいでも消えません。金床や砥石で修理しても、この記録は消せません(意図的にブロックされています)。

この記事自体は、どの仕組みも新しく追加したり、既定値を変えたりするものではありません。すでに動いている仕組みを、書き漏れていた分もあわせてまとめて書き起こしただけです。挙げた config キーは、すべてサーバー側の config/sorakaze_*.json の中にあります。書きかえられるのはサーバー管理者だけです。
