概要:Glimpse Alpha の導入について

Glimpse Alpha(旧称: Sorakaze)は、そらかぜからすサーバーに導入されている Fabric MOD 群です。11 個の独立した MOD で構成されており、それぞれ個別に導入・更新できます。 弓矢やトロッコなどバニラ(MOD なしの標準)の要素を置き換えたり削除したりはせず、 新しいアイテム・ブロック・ディメンションを追加する形になっています。

MOD内容
銃火器バニラにない遠距離武器(アサルトライフル・ショットガン・スナイパーなど)
鉄道だんだん速くなる電車と、連結できる客車・貨物車
建材・装飾信号機・ガードレールなど街づくり用の建材と、防犯カメラ・ATM・エレベーターなどの家電
乗り物自動車・バス・航空機など
ボス強力な討伐対象と、専用のドロップ装備
天空新しいディメンション「天空」と、そこに住む天使の街・王国
サバイバル新しい鉱石・防具や、気温・四季といった生活要素
電力発電・送電網と、電気で動く機器
バックルームズ正気度つきの異界探索。終末の都市の裂け目から迷い込む隠しコンテンツ

各 MOD の詳しいアイテム・レシピはレシピ集、これまでの変更点は 更新履歴を参照してください。

MOD を使うには「Fabric」が必要

Fabric(ファブリック)は、Minecraft に MOD を読みこませるための土台です。 ゲーム機にソフトを入れる前に本体のシステムが必要なのと同じイメージで、 MOD 本体を入れる前に、まずサーバーと各プレイヤーの PC の両方に Fabric を導入する必要があります。

⚠ いちばん間違えやすいポイント

MOD はサーバーだけでなく、遊ぶ人全員の PC にも同じものを入れる必要があります。 「サーバーに入れれば全員に自動で反映される」ということはありません。 サーバーと全プレイヤーの Minecraft バージョン・Fabric・MOD の組み合わせがそろっていないと、 サーバーに参加できません。

だれが何を用意するか

  • サーバー(そらかぜからす鯖) — Fabric サーバー本体 + Fabric API + Glimpse Alpha 11 MOD
  • 参加する人 1 人 1 人の PC — Fabric クライアント + Fabric API + Glimpse Alpha 11 MOD(サーバーと完全に同じ組み合わせ)
MOD 本体はこのサイトでは配布していません

このサイトはレシピ表・更新履歴・導入手順などの「読みもの」だけを掲載しており、 MOD 本体(jar ファイル)そのものは配布していません。導入に必要な jar ファイル一式は サーバー管理者から受け取ってください。

このページの構成

このガイドは 2 つの立場に分けて書かれています。ほとんどの方は プレイヤー向けの章だけ読めば参加できます。 自分でサーバーを運用する・管理する立場の方は、続けて サーバー管理者向けの章もご覧ください。

プレイヤー向け

プレイヤー向け:サーバーに参加するための設定

ここでは、サーバーに遊びに行く側の設定を説明します。むずかしい専門知識は不要です。 上から順番にやれば、だいたい 15〜20 分で終わります。

やることは 3 つだけ
  • ① Fabric(MOD を読みこむ土台)を自分の PC に入れる
  • ② サーバー管理者から受け取った MOD ファイル一式を、決まったフォルダーに入れる
  • ③ 起動のしかたを 1 か所だけ変えて、サーバーに参加する

用意するもの

  • Minecraft Java 版が遊べる Windows または Mac の PC
  • サーバー管理者から受け取った MOD 一式(jar ファイル 12 個 = Fabric API 1 個 + Glimpse Alpha の MOD 11 個)
🛑 とても大事

サーバーとまったく同じバージョン・まったく同じ MOD ファイルでないと参加できません。 このページでは例として Minecraft バージョン 26.2 と書きますが、 サーバー管理者から別の数字を伝えられた場合はその数字に読みかえてください。 受け取った jar ファイルはダブルクリックして開かないでください。フォルダーに置くだけで使えます。

受け取る予定のファイル(例)

サーバー管理者から、だいたい次のような 12 個のファイルを受け取ります(バージョン番号は更新のたびに変わります)。

① Fabric をインストールする

https://fabricmc.net/use/installer/ を開き、インストーラーを入手します。「Client」タブのまま(「Server」に切りかえない)、Minecraft Version にサーバーと同じ数字を選んで「Install」を押します。

Windows の場合

  1. ページの「Download installer (Windows/.exe)」のようなボタンからインストーラーをダウンロードし、ダブルクリックで実行します(「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」を押します)。
  2. 「Client」タブのまま、Minecraft Version に 26.2(サーバーと同じ数字)を選び、Loader Version はそのままで「Install」を押します。

Mac の場合

  1. 「Download universal jar」ボタンからインストーラー(.jar)をダウンロードします。Mac 用の実行ファイル(.exe)はありません。
  2. ダウンロードした fabric-installer-〜.jar を、ふつうのダブルクリックではなく、右クリック(または control キーを押しながらクリック)して「開く」を選びます。警告が出たら、もう一度「開く」を押します。
  3. 「Client」タブのまま、Minecraft Version にサーバーと同じ数字を選んで「Install」を押します。
⚠ Mac で「開発元を検証できません」と出たら

最近の macOS では、右クリック→「開く」でもボタンが出ず、 「"fabric-installer〜.jar" にマルウェアが含まれていないことを検証できませんでした」という警告だけが出ることがあります。そのときは次の順番で開けます。

  1. 警告では「完了」を押す(「ゴミ箱に入れる」は絶対に押さない)
  2. 画面左上の Apple メニュー →「システム設定」→「プライバシーとセキュリティ」を開く
  3. 下のほうに「"fabric-installer〜.jar" の使用はブロックされました」という表示があるので、横の「このまま開く」を押す
  4. もう一度聞かれたら「このまま開く」→ Mac のパスワード(または Touch ID)を入力

これは Apple に登録されていない配布物すべてに出る標準的な警告で、Fabric 公式サイトから入手していれば心配いりません。一度許可すれば、次からは普通に開けます。

Mac でインストーラーが何も起きない場合

右クリック→「開く」をしても何も起きない場合、システムに Java が入っていません。 adoptium.net を開き、「Temurin」の macOS 用インストーラー(.pkg)を入れてからもう一度試してください。 Apple シリコン(M1/M2/M3/M4 など)の Mac は「aarch64」、Intel の Mac は「x64」を選びます。 わからない場合は画面左上の Apple メニュー →「この Mac について」の「チップ」欄を確認してください(「Apple M〜」とあれば aarch64 です)。

② MOD ファイルを mods フォルダーに入れる

Windows: %appdata%\.minecraft\mods

  1. エクスプローラーのアドレス欄に %appdata%\.minecraft と入力して Enter を押します。
  2. mods フォルダーがなければ新規作成します(すべて小文字)。
  3. 受け取った 12 個の jar ファイルをすべて、この mods フォルダーの中にコピーします(解凍は不要、jar のまま入れます)。

Mac: ~/Library/Application Support/minecraft/mods

  1. デスクトップを 1 回クリックしてから、⌘ command+⇧ shift+G を同時に押します(または上部メニューの「移動」→「フォルダへ移動…」)。
  2. 出てきた入力欄に ~/Library/Application Support/minecraft をそのまま貼り付けて Enter を押します(先頭の「~」も忘れずに)。「Library」は Finder では普段見えないフォルダーなので、この方法で開くのが確実です。
  3. mods フォルダーがなければ、その場で右クリック→「新規フォルダ」で作成します。
  4. 受け取った 12 個の jar ファイルをすべて、ドラッグ&ドロップでこの mods フォルダーに入れます。

③ Fabric で起動してサーバーに参加する

  1. Minecraft ランチャーを開き、「プレイ」ボタンの近くにある起動構成(プロファイル)の一覧から fabric-loader-26.2 のような名前を選びます(「最新のリリース」のままだと MOD なしで起動してしまいます)。
  2. そのまま「プレイ」を押して起動します。タイトル画面に「Mods」ボタンが増えていれば成功です。押すと Glimpse Alpha の MOD 11 個と Fabric API が確認できます。
  3. あとはいつもどおり「マルチプレイ」からサーバーに接続します。

MOD が更新されたとき

サーバー側の MOD が更新されたら、参加者全員が同時に同じ版へ更新する必要があります。

  1. サーバー管理者から新しい MOD ファイルを受け取る(通知を待ってから作業してください)。
  2. mods フォルダーを開き、これまで入っていた Glimpse Alpha の jar ファイルを削除してから、新しいファイルを入れる(ファイル名が変わっていても中身は同じ MOD として扱われるため、古いものが残っていると起動できません)。
  3. いつもどおり fabric-loader のプロファイルで起動する。
⚠ 注意

片方だけ新しい版のままだとサーバーに参加できません。困ったときはよくある質問も確認してください。

Mac でよくあるつまずき

症状直しかた

サーバー管理者向け

サーバー管理者向け:事前準備(バックアップとバージョン確認)

ここからはサーバー本体を運用・管理する立場の方向けの章です。すでに Minecraft の サーバー(バニラ、MOD なしの標準サーバー)が動いている状態から、Fabric と Glimpse Alpha の 11 MOD を追加する手順を説明します。この章では Windows サーバーを例にします。 Mac / Linux でサーバーを運用している場合は、フォルダーの場所やコマンドの実行方法をご自身の 環境に読みかえたうえで、同様の手順(Fabric 公式サイトの案内)に沿ってください。

🛑 作業前に必ず

MOD の導入で失敗してもワールドを失わないよう、必ずバックアップを取ってから作業を始めてください。

1. ワールドのバックアップを取る

サーバーのフォルダー(例: C:\MinecraftServer)を開き、普段使っているバックアップ手順(例: Backup-Server.bat のようなバックアップ用スクリプト)を実行します。専用のスクリプトがない場合は、サーバーを停止した状態で world フォルダーをまるごと別の場所にコピーしておくだけでも構いません。

2. Java のバージョンを確認する

  1. コマンドプロンプト(または任意のターミナル)を開きます。
  2. java -version と入力して Enter を押します。
  3. 表示された数字が 25 かどうかを確認します(例: java version "25.0.3")。
🛑 とても大事

Minecraft 26.2 を動かすには Java 25 が必要です。古いセットアップ手順に 「Java 21」と書かれていることがありますが、これは古い情報で、Java 21 のままではサーバーが起動しません。 数字が 25 未満の場合は adoptium.net を開き、 「Temurin 25 (LTS)」をダウンロード・インストールしてから、パソコンを再起動してもう一度確認してください。

3. サーバーの Minecraft バージョンを確認する

  1. 普段どおりの方法(例: Start-Server.bat)でサーバーをいったん起動します。
  2. コンソール(黒い画面)の最初のほうに出る Starting minecraft server version X.Y のような行を探し、その数字をメモします。
  3. コンソールに stop と入力して Enter を押し、サーバーを安全に停止します。
⚠ 注意

このガイドでは例として「26.2」と表記していますが、実際に確認した数字が違う場合は、 以降すべての手順(Fabric・Fabric API・MOD の各バージョン選択)をその数字に読みかえてください。 サーバー・すべてのプレイヤー・MOD のバージョンが 1 つでもそろっていないと、まったく動きません。

サーバー管理者向け

サーバー管理者向け:Fabric の導入

Fabric サーバーをインストールする

  1. ブラウザで https://fabricmc.net/use/server/ を開き、「Download installer (Windows/.exe)」のようなボタンからインストーラーをダウンロードします。
  2. ダウンロードした fabric-installer〜.exe をダブルクリックして起動します(「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」)。
  3. インストーラーの設定画面で次の 4 点を確認します。
    • タブは「Server」を選ぶ
    • Minecraft Version は、事前準備で確認したサーバーのバージョン(例: 26.2)と同じものを選ぶ
    • Loader Version はそのままで OK
    • Install Location は既存のサーバーフォルダー(例: C:\MinecraftServer)を指定する
  4. 「Install」を押します。
  5. サーバーフォルダーの中に fabric-server-launch.jar という新しいファイルができていれば成功です。

新しい起動用ファイル(バッチファイル)を作る

今までの起動用ファイル(例: Start-Server.bat)は「MOD なし」を起動するファイルです。 これは消さずに残しておきます(もしもの時に MOD なしへ戻れるように)。 代わりに、Fabric 用の新しい起動ファイルを作ります。

  1. メモ帳(Notepad)を開きます。
  2. 次の内容をそのままコピーして貼り付けます。 
    @echo off
cd /d "%~dp0"
title Minecraft Fabric Server
java -Xms2G -Xmx4G -jar fabric-server-launch.jar nogui
echo サーバーが停止しました。
pause
  3. 「ファイル」→「名前を付けて保存」で、保存する場所をサーバーフォルダー(例: C:\MinecraftServer)、ファイル名を Start-Fabric-Server.bat、ファイルの種類を「すべてのファイル」にして保存します。
⚠ 注意

「ファイルの種類」を「すべてのファイル」にしないと、Start-Fabric-Server.bat.txt という動かないファイルになってしまいます。また、サーバー構築時に確保したメモリ(RAM)が 4GB 以外の場合は、-Xmx4G の「4」をその数字に書きかえてください。

サーバー管理者向け

サーバー管理者向け:MOD の導入と起動確認

MOD の本体は「jar(ジャー)ファイル」という 1 個ずつのファイルです。これをサーバーフォルダーの mods フォルダーに入れるだけで導入できます。

1. mods フォルダーを用意する

サーバーフォルダー(例: C:\MinecraftServer)の中に mods という名前のフォルダーがあるか確認します。なければ、右クリック→「新規作成」→「フォルダー」で mods(すべて小文字)という名前で作ります。

2. Fabric API を入手する

https://modrinth.com/mod/fabric-api/versions を開き、一覧から「Game version(ゲームバージョン)がサーバーと同じ数字」になっている一番上のものをダウンロードします(例: fabric-api-0.154.2+26.2.jar)。

3. MOD 一式を mods フォルダーに入れる

Fabric API 1 個 + Glimpse Alpha の MOD 11 個、合計 12 個の jar ファイルを mods フォルダーの 中にコピーします(解凍は不要、jar ファイルのまま入れます)。この 11 個の MOD 本体は、これまでどおりの 配布経路で入手してください。このサイトでは MOD 本体そのものは配布していません。

サーバー管理者向け

MOD を新しい版に入れかえるとき

Glimpse Alpha は 11 個の MOD がそれぞれ完全に独立しているため、更新のたびに 11 個すべてが 差し替わるとは限りません。実際に中身が変わった MOD だけを入れかえれば大丈夫です (どの MOD が変わったかは、配布時の案内や更新履歴で確認できます)。

更新の手順

  1. サーバーのコンソールに stop と入力してサーバーを止める。
  2. いつものバックアップ手順でワールドのバックアップを取る。
  3. サーバーの mods フォルダーの中にある、更新対象の MOD の古い jar ファイルを削除し、新しい jar ファイルを入れる(同じ MOD の新旧が両方残っていると起動できません)。
  4. Start-Fabric-Server.bat でサーバーを起動し、コンソールに更新後のバージョンが表示されることを確認する。
  5. 参加者全員にも新しい jar ファイルを配布し、同じように入れかえてもらう(プレイヤー向けの章参照)。サーバー側だけ・プレイヤー側だけが新しい版になっている状態では、参加できません。
🛑 とても大事

MOD を(更新ではなく)完全に外した状態でサーバーを起動すると、その MOD で置いたブロックや 持っていたアイテム(信号機など)は消えます。これは Minecraft・Fabric の仕様であり、元に戻せません。 外す前に必ずバックアップを取ってください。

config ファイルについて(自動修復のしくみ)

各 MOD は起動時に config/ フォルダーの中に設定ファイル(例: sorakaze_guns.json)を 自動生成します。威力や速度などの数値はここで調整でき、更新のたびに手動で消したり書きかえたりする必要は 基本的にありません。

💡 現在のしくみ

新しい版で既定値が変わった項目は、まだ調整していない(古い既定値のままの)項目に限って 自動的に新しい既定値へ更新されます。ご自分で調整した値には触れません。 新しく追加された設定項目も、起動時に自動で書き足されます。何が更新されたかは logs/latest.log に「古い値 → 新しい値」の形で必ず記録されます。

⚠ 設定ファイルを編集するときの注意

設定ファイル内の値の一部だけを手作業で削除すると(例: ある武器の設定のかたまりから ダメージの行だけを消す)、その項目が MOD 内部の別の初期値に静かに置き換わってしまうことがあります (エラーは出ません)。特定の数値を調整したいときは、その項目の値を直接書きかえるようにしてください。 設定を丸ごと初期状態に戻したい場合は、該当する MOD の設定ファイルごと削除すれば、次回起動時に 既定値で作り直されます。

サーバー管理者向け

ゲーム内「管理者アプリ」のID・パスワードを設定する

Apple端末(iPhone / MacBook / Mac Studio)を右クリックして開く Mine OS のホーム画面には、真鍮色の南京錠のアイコンをした「管理者」アプリがあります。 ここでは、そのアプリのID・パスワードを所有者(サーバー管理者)が自分で設定・変更する方法を説明します。

💡 このページを読めることと、アプリに入れることは別です

この手順を知っているだけでは管理者アプリにはログインできません。ログインには あなたが実際に選んだIDとパスワードの両方が必要で、それは以下の手順で あなた自身のサーバーの中だけに置かれます。手順を公開しても、 実際のID・パスワードを知らない人がアクセスできるようになるわけではありません。

出荷時点の既定値

何も設定していない場合、管理者アプリは出荷時点の既定のID・パスワードを使います。 実際に配布・運用する前に、必ず自分だけのID・パスワードへ変更してください。 MODの中に入っているのはパスワードそのものではなく、 照合用の記録(PBKDF2-HMAC-SHA256、210,000回、salt付き)だけです。 この記録から元のパスワードを逆算することはできません。

自分のID・パスワードに変更する手順

  1. サーバーのソース一式(mods-src)がある環境で、次のコマンドを実行します (<好きなID>は他で使っていない文字列に置きかえてください)。 
    python3 tools/make_admin_account.py --id <好きなID> --merge config/sorakaze_deco/admin_account.json
  2. 新しいパスワードを2回訊かれます(画面には表示されません)。 このパスワードはコマンド自身には一切書き込まれず、選んだ本人の頭の中とメモだけに残ります。
  3. 実行すると、照合用の記録(salt・反復回数・ハッシュのみ)が config/sorakaze_deco/admin_account.json として書き出されます。
  4. サーバーを再起動してください。このファイルが在れば必ずこちらが既定値に優先します。
⚠ 再起動すると、入っている管理者セッションは全部切れます

古いID・パスワードでログインしていた人は、その時点で締め出されます。 管理者を選び直した・パスワードが漏れた、といった場面でそのまま使える安全装置です。

IDとパスワードの配布

新しいIDとパスワードは、あなたが選んだ管理者にだけ、あなた自身の手で伝えてください。 「ゲーム内チャットで新しいパスワードを発行して表示する」ような機能は、この管理者アプリには 意図的に用意していません。ゲーム内チャットはサーバーのログに残り、ログは 多くの場合そのまま共有・保存されるため、パスワードをチャットに書いた時点でそれは漏洩したのと 同じ扱いになります。

既定値へ戻したいとき

config/sorakaze_deco/admin_account.json を削除してサーバーを再起動すれば、 出荷時点の既定のID・パスワードへ戻ります。

遊ぶ前に知っておきたい注意点

Glimpse Alpha はバニラの挙動に影響する変更もいくつか含んでいます。ここでは特に見落としやすい ものをまとめています。細かい数値は更新のたびに調整されることがあるため、最新の状況は 更新履歴や既知の不具合ページも あわせて確認してください。config の調整はサーバー管理者が行うものです。

レッドストーンに「電気」が必要

電力 MOD の導入により、バニラのレッドストーンの一部が単体では動かなくなります。

  • 電気が必要になるもの: レッドストーンの粉・反復装置(リピーター)・比較装置(コンパレーター)・レッドストーンブロック・レッドストーントーチ。これらはケーブルで電気をつなぐまで信号を出しません。自動農場・駅・自動ドア・ホッパーの列は、配線するまで止まったままになります。
  • 電気がなくても今までどおり使えるもの: レバー・ボタン・感圧板・トリップワイヤーフック・オブザーバー・日照センサー・スカルクセンサー・的(ターゲット)・トラップチェスト・ディテクターレール・書見台・ジュークボックス・避雷針など。ドアや門を手で開ける操作もそのまま使えます。
  • 設置後 10 分ほど経つとレッドストーンブロックは自然に壊れます(アイテムとして手元に戻ります)。
💡 元に戻す方法(サーバー管理者向け)

config/sorakaze_power.json の powerEnabled を false に すると、レッドストーンの電化を丸ごと無効化できます。

建材・装飾の一部機器も電気が必要

防犯カメラ・エレベーター・エスカレーター・自動ドア・ATM の 5 つは、ケーブルで電気を引いていないと 動きません(エレベーターは電気がなくても「下り」だけは動くようになっています)。 機器ごとに config/sorakaze_deco.json の該当項目を false にすると、個別に電気を不要にできます。

発電機は部屋を暑くする

動いている発電機・原子力発電所は、同じ空間の気温を上げます。冷やせるのはエアコンだけです。 機械室を壁と閉じたドアで区切っておくと、熱が他の部屋に広がらず簡単に対策できます。 この機能自体は config/sorakaze_survival.json の temperatureMachineHeatEnabled を false にすると無効化できます。

天空の世界の高さが拡張されている

天空 MOD の導入により、通常世界(オーバーワールド)で建築できる高さの上限が引き上げられています。 変わるのは空側の上限だけで、地下の深さ(底の高さ)や既存の地形はそのままです。

ロケットランチャーは地形を破壊する

銃火器 MOD のロケットランチャーは、既定の設定では着弾地点の地形を破壊します。 バニラのゲームルール mobGriefing を false にしても止まりません。 破壊を止めるには config/sorakaze_guns.json の rocketDestroysTerrain を false にする必要があります。拠点の近くでは特に注意してください。

銃の火力について

銃火器 MOD の武器、特にアサルトライフルは非常に高い火力を持っており、MOD 追加のボスの多くは 数秒で倒せてしまいます。歯ごたえが欲しい場合は、サーバー管理者が config/sorakaze_guns.json の各武器のダメージ値を調整することで難易度を戻せます。

MOD を外すと、置いたブロック・アイテムは消える

これは MOD 一般の仕様であり、Glimpse Alpha 特有の不具合ではありません。MOD を導入した状態で 設置したブロックや入手したアイテムは、その MOD を外すとワールドから失われます。元に戻すには バックアップから復元するしかありません。
