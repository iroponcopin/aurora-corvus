Corvus

Corvus는 Alpha MOD 팩을 자동으로 최신 상태로 유지해 주는 작은 데스크톱 앱입니다. 이 Wiki를 보고 최신 릴리스를 확인하고, 업데이트분을 다운로드하며, 팩 폴더에 손을 대기 전에 다운로드한 파일을 모두 이 Wiki가 공개하는 SHA-256 체크섬과 대조합니다. 신뢰하는 정보원은 이 Wiki뿐입니다.

Corvus란 무엇이며, 왜 만들어졌는가

큰 MOD 팩을 수동으로 최신 상태로 유지하려면, 다운로드 페이지를 방문해 버전 번호를 비교하고, 새 ZIP을 다운로드하고, 릴리스가 나올 때마다 올바른 폴더에 다시 압축을 풀어야 합니다. Corvus는 이 과정을 자동화합니다 ―― 이 Wiki의 릴리스 정보를 읽어, 지금 설치되어 있는 팩과 비교해 변경된 분량만 가져옵니다.

런처가 다운로드하는 파일은 사용하기 전에 반드시 이 Wiki가 공개하는 SHA-256 체크섬과 대조됩니다. 일치하지 않으면 그 파일은 설치되지 않습니다. 「최신판이란 무엇인가」에 대해 런처가 신뢰하는 정보원은 이 Wiki뿐입니다.

Corvus 설치 방법

Corvus는 이 Wiki의 다운로드 페이지에서, MOD 팩 ZIP과 같은 곳에 2가지 형태로 배포되고 있습니다.

  • OS별 네이티브 설치 프로그램(Windows용 .msi·macOS용 .dmg·Linux용 .deb) ―― 일반 데스크톱 앱과 같은 절차로 설치할 수 있으며, Java는 필요 없습니다. 아직 코드 서명을 하지 않았기 때문에, 처음 실행할 때 OS에서 경고가 표시됩니다. macOS에서는 더블 클릭 대신 앱을 오른쪽 클릭해 「열기」를 선택해 주세요. Windows에서는 SmartScreen 경고에서 「추가 정보」 → 「실행」을 선택해 주세요.
  • 크로스 플랫폼 jar corvus-1.7.0.jar ―― 같은 파일 하나가 Windows·macOS·Linux 어디에서나 동작하지만, 미리 Java 21 이상이 설치되어 있어야 합니다. 더블 클릭으로 열리지 않는 경우에는, 다운로드한 폴더에서 터미널(또는 명령 프롬프트)을 열고 java -jar corvus-1.7.0.jar를 실행해 주세요.

기존 MOD 팩 폴더를 지정하기

이미 Alpha MOD 팩을 수동으로 설치했더라도, 처음부터 다시 할 필요는 없습니다. 처음 실행할 때 폴더를 새로 만드는 대신, 기존 MOD 팩이 들어 있는 폴더를 선택할 수 있습니다. 기존 mods 폴더를 지정하면, 이후로는 그 설치본을 런처가 관리하는 대상으로 다룹니다.

자동 업데이트 모드와 수동 업데이트 모드의 차이

자동 업데이트 모드에서는 런처가 이 Wiki의 릴리스 정보를 스스로 확인해, 새 버전이 공개되는 대로 설치합니다. 아무것도 하지 않아도 팩 폴더는 항상 최신 상태로 유지됩니다.

수동 업데이트 모드에서는 런처가 업데이트 유무를 확인하지만, 다운로드나 설치를 하기 전에 사용자의 확인을 기다립니다. 플레이 중에 업데이트가 끼어드는 것을 피하고 싶을 때 등, 업데이트 시점을 직접 고르고 싶은 경우에 편리합니다.

업데이트가 실제로 반영되었는지 확인하는 방법

버전 1.1.0부터, Update를 누르면 새 MOD 파일이 팩의 mods 폴더에 직접 기록됩니다. 업데이트 후에 폴더의 내용을 실제로 다시 확인해, 기대한 파일이 존재한다는 것을 확인할 수 있을 때까지는 「Update complete」라고 표시되지 않습니다. 도중에 무언가 실패한 경우에는, 거짓 성공 표시가 아니라 실패로 보고합니다.

macOS에서 실제로 확인하는 방법: 설정 화면에 표시된 폴더를 열고(Finder에서 ⌘+⇧+G를 눌러 경로를 붙여넣기), mods 안을 보고, Update 전후로 각 alpha-*.jar 파일명 안의 버전 번호를 확인해 주세요.

1.1.0보다 이전 버전의 런처가 마지막으로 손댄 팩 폴더에서 업데이트하는 경우, 처음 한 번만 그 MOD의 예전 버전 jar가 새 jar와 나란히 남는 경우가 있습니다(그 이전의 런처에는 자신이 어떤 파일을 배치했는지에 대한 기록이 없었기 때문입니다). 다음 업데이트부터는 자동으로 해소됩니다. 당장 신경 쓰이는 경우에는, 새 파일이 있다는 것을 확인한 뒤 예전 버전의 alpha-*.jar를 직접 삭제해도 문제없습니다.

업데이트에 실패했을 때 백업에서 복원하기

업데이트한 결과 MOD의 오작동 등 원하지 않는 상태가 되어 버린 경우나, 업데이트를 취소하고 싶은 경우를 위해, 런처는 업데이트 전 팩의 상태를 백업으로 보관하고 있습니다. 파일을 손으로 직접 고치려 하지 말고, 런처의 복원 기능을 사용해 팩 폴더를 백업 시점의 상태로 되돌려 주세요.
