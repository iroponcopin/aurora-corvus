Corvus

Corvus 是一款小巧的桌面应用，它会自动把 Alpha 整合包保持在最新状态。它会查阅本 Wiki 确认最新的发布版本，下载更新的部分，并在改动整合包文件夹之前，把下载到的所有文件与本 Wiki 公开的 SHA-256 校验和逐一比对。它唯一信任的信息来源就是本 Wiki。

Corvus 是什么，为什么要做它

要手动把一个大型整合包保持在最新状态，就得每次发布时都造访下载页面、对比版本号、下载新的 ZIP，并重新解压到正确的文件夹中。Corvus 把这些都自动化了 —— 它会读取本 Wiki 的发布信息，与您当前已安装的整合包进行比较，只获取有变动的部分。

启动器下载的文件，在使用之前一定会与本 Wiki 公开的 SHA-256 校验和进行比对。如果不一致，该文件就不会被安装。关于「什么才是最新版本」，启动器唯一信任的信息来源就是本 Wiki。

Corvus 的安装方法

Corvus 在本 Wiki 的下载页面上，与整合包的 ZIP 放在同一处，以 2 种形式分发。

  • 各操作系统的原生安装程序（Windows 用 .msi、macOS 用 .dmg、Linux 用 .deb） —— 可以按与普通桌面应用相同的步骤安装，不需要 Java。由于我们尚未进行代码签名，首次启动时操作系统会显示警告。在 macOS 上，请不要双击，而是右键点击应用并选择「打开」。在 Windows 上，请在 SmartScreen 的警告中选择「更多信息」→「仍要运行」。
  • 跨平台的 jar corvus-1.8.0.jar —— 同一个文件在 Windows、macOS、Linux 上都能运行，但需要事先安装好 Java 21 或更高版本。如果双击打不开，请在下载该文件的文件夹中打开终端（或命令提示符），执行 java -jar corvus-1.8.0.jar。

指定已有的整合包文件夹

即使您已经手动安装好了 Alpha 整合包，也不需要从头再来一遍。首次启动时，可以不新建文件夹，而是选择已有整合包所在的文件夹。只要指定现有的 mods 文件夹，此后启动器就会把那一份安装当作自己管理的对象。

自动更新模式与手动更新模式的区别

在自动更新模式下，启动器会自行查阅本 Wiki 的发布信息，一旦有新版本公开就立即安装。您什么都不用做，整合包文件夹也会始终保持在最新状态。

在手动更新模式下，启动器仍会确认有没有更新，但在下载和安装之前会等待您确认。如果希望自己选择更新的时机，例如不想让更新打断正在进行的游戏，这个模式会很方便。

如何确认更新真的生效了

从 1.1.0 版起，按下 Update 后，新的 MOD 文件会被直接写入整合包的 mods 文件夹。在更新之后实际重新检查文件夹的内容、确认预期的文件确实存在之前，界面不会显示「Update complete」。如果中途出现任何失败，它会如实报告失败，而不是给出虚假的成功提示。

在 macOS 上实际确认的方法：打开设置界面中显示的那个文件夹（在 Finder 中按 ⌘+⇧+G 并粘贴路径），查看 mods 的内容，比对 Update 前后各个 alpha-*.jar 文件名中的版本号。

如果您是从最后一次由 1.1.0 之前版本的启动器改动过的整合包文件夹进行更新，那么仅限最初的 1 次，该 MOD 的旧版本 jar 有可能与新的 jar 并存（这是因为更早的启动器没有记录自己放置过哪些文件）。从下一次更新开始就会自动消除。如果您想马上处理，也可以在确认新文件确实存在之后，手动删除旧版本的 alpha-*.jar，这不会有问题。

更新失败时从备份还原

为了应对更新之后陷入 MOD 故障等不希望出现的状态，或者您想撤销这次更新的情况，启动器会把更新前整合包的状态保留为备份。请不要试图手动去修复文件，而是使用启动器的还原功能，把整合包文件夹恢复到备份时的状态。
